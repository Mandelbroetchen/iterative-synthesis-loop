## Part 3: Validation & Improvement Requirements

### Rules
1. **Only write to files listed by `overwrite.py`** — `overwrite.py` is the single output file used to update `code-final/`.
2. **Preserve public APIs** unless the design or tests demand breaking changes; document any breaking changes inside the `overwrite.py` content (as non-executed strings if necessary).
3. **Follow language best practices** (for Python projects follow PEP 8, type hints where appropriate, comprehensive error handling).
4. **Add or update tests** where missing: include minimal unit tests that validate the key behaviors.
5. **No external network calls** during analysis — assume static reasoning and local execution only.

### Validation Checklist
- [ ] Code is syntactically correct and imports resolve
- [ ] Core functionality matches documented behavior or inferred intent
- [ ] Edge cases and error handling are covered
- [ ] No insecure patterns or obviously unsafe operations
- [ ] Functions and classes include docstrings and reasonable type hints
- [ ] Minimal tests exist and are runnable
- [ ] No leftover TODOs or debugging prints
- [ ] Also generate a file `.patchnote.md` to address everything that has been changed by you.

## Part 4: Required Deliverable (STRICT)

You must respond with exactly one file named `overwrite.py` (the LLM output must be the contents of that file and nothing else). The file must be pure Python code with the following properties:

- Creates or updates one or more files under `code-final/` based on improved contents derived from `code-raw/`.
- Encodes complete, production-ready content for each target file as UTF-8 strings.
- Creates directories as needed: `Path(...).parent.mkdir(parents=True, exist_ok=True)`.
- Executes without raising exceptions when run in the repository root.
- Prints a single success message upon completion (for example: `print("✓ code-final updated")`).
- Must not print or emit any other text, and must not include non-Python preamble or trailing explanation.

### Template Structure (required shape)

```python
from pathlib import Path

files = {
    "code-final/__init__.py": """[Complete, improved Python code for __init__.py]""",
    "code-final/module_a.py": """[Complete, improved Python code for module_a]""",
    "code-final/module_b.py": """[Complete, improved Python code for module_b]""",
    "code-final/tests/test_module_a.py": """[Minimal tests validating key behaviors]""",
}

for path, content in files.items():
    Path(path).parent.mkdir(parents=True, exist_ok=True)
    Path(path).write_text(content, encoding="utf-8")

print("✓ code-final updated")
```

Do not include any additional output or explanation beyond the Python code. The content strings must contain the full file contents exactly as they should appear on disk.
